## 0. Summary

**What is good.** The September infrastructure work landed: one shared `makeSupabaseFake` (54 of 55 DB-touching suites use it, zero hand-rolled `from: vi.fn` chains remain), `server-fn-stub` + `impersonate` + `expectDeniedCrossUser`, the folder-write oracle and its on-disk registry, an in-process cron-route auth sweep, global mock/env/timer teardown, UTC pinning, a coverage ratchet in CI. Type discipline in tests is high: 0 `as any`, 25 `as unknown as`, 1 `@ts-expect-error`. Mock depth is appropriate — no test mocks the module it tests; pure logic (vCard parser, filter engine, decision ladder, merge) stays real in pipeline tests.

**What is wrong, in priority order.**

1. **Untested code hides real security bugs** (§1). Two cross-tenant IDORs, PII retained after account deletion, unauthenticated unthrottled writes, a prompt-injection channel, and a Gmail "404" string-sniff that makes reconcile delete local rows. All in 0–45 %-covered modules.
2. **The CI integration job has never passed** (§2.1). `supabase db reset` fails on `cron.schedule` being called one migration before `create extension pg_cron`. The only DB-level RLS/IDOR proofs run nowhere. `main` is red.
3. **Fixture fidelity gaps make whole branches unfalsifiable** (§2.2). The fake's `ilike`/`contains`/`or` are pass-throughs, the write-builder `.select()` is not thenable, `.select()` can never error, writes don't mutate seeded rows. At least 12 existing tests pass regardless of the behaviour they name because of this.
4. **The known-bug register has drifted** (§3). Of the 19 bugs in the September memory note, at least 7 described as "pinned" are not actually pinned by any test. Nothing is grep-able as a characterization pin.
5. **~80 exported server functions that take a client-supplied id have no cross-user test** (§4), while the fixture built for exactly that (`idor.ts`) is used by 4.
6. **Theater and duplication** (§5): 13 of 22 in-person-transcript tests cannot fail, four source-grep tests, the classification ladder specified four times, ~100-line mock preambles copied 4× (gmail fns) and 4× (CardDAV handlers) and 3× (run-jobs), 7 misplaced `sync-*.test.ts` files, 49 copies of a `vi.mock` hoisting workaround.

The plan (§7) is six phases. Phase 0 (CI green + the six verified bugs, each landed with a failing test first) is about a week and should start immediately. Phases 1–2 are the foundation and security sweep and unlock everything after them.

## 6. Conventions to adopt (write into README "Test conventions")

1. **File naming.** `<module>.test.ts` beside the module. Exactly two suffix classes: `<module>.<topic>.test.ts` for a split of a too-long file; `<module>.<kind>.test.ts` with `kind ∈ {snapshot, regression, security, edge}`. `tests/*.integration.test.ts` = needs `TEST_DATABASE_URL`; `tests/*.live.test.ts` = needs a deployed URL.
2. **Characterization.** `// CHARACTERIZATION(<slug>): <what is wrong> — flip when fixed` above the `it`. A registry test greps the tag and fails on an unknown slug; the plan's bug table is generated from it.
3. **Env.** `vi.stubEnv` only (`vi.stubEnv("X", undefined)` to unset). Lint: `no-restricted-syntax` on `process.env` assignment in test files.
4. **Time and randomness.** `vi.useFakeTimers({ now })` + `vi.setSystemTime`; `vi.spyOn(Math, "random")`. No `Date.now()` windows, no `elapsed <` assertions.
5. **Mocks.** `vi.hoisted` + `vi.fn<typeof import("./x").fn>()`; factories `satisfies Partial<typeof import("./x")>`; no `(...args) => mock(...args)` wrappers; no `mockClear`/`clearAllMocks` (config does it).
6. **Fixtures.** Typed row factories (`makeContactRow`, `makeFolderDbRow`, …) over `Record<string, unknown>` seeds; `satisfies` over `as`; no `as unknown as` for partial domain objects — extend the factory instead.
7. **Assertions.** `toStrictEqual` for value equality; full-payload assertions on RPC/Gmail calls; `expectDeniedCrossUser` for every server fn taking an id; call-_order_ assertions where the audit's bug class is "non-transactional".
8. **Lint.** `@vitest/eslint-plugin` scoped to `**/*.test.{ts,tsx}` and `tests/**`: `no-focused-tests`, `no-disabled-tests`, `expect-expect` (assertFunctionNames: `expect*`), `no-conditional-expect`, `valid-title`, `no-identical-title`, `no-standalone-expect`, `prefer-strict-equal` (warn, ratchet); `@typescript-eslint/consistent-type-assertions` with `objectLiteralTypeAssertions: "never"`.
